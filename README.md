# Modbus 协议转换网关

工业现场常用的协议转换网关全栈实现：下位通过 RS-485 采集 Modbus-RTU 设备，  
上位提供 Modbus-TCP 服务端供 SCADA / PLC / Modbus Poll 接入，配套一套 Linux  
上位机完成多网关并发采集、历史存储、Web 仪表盘与远程固件升级。

**子模块说明**：[`stm32-gateway/`](stm32-gateway/README.md)（网关固件 + Bootloader）·  
[`linux-host/`](linux-host/README.md)（Linux 上位机）·  
[`stm32-gateway/NET/context.md`](stm32-gateway/NET/context.md)（引脚与端口配置）

---

## 1. 项目背景

工业现场有大量仪表（温湿度变送器、电表、流量计、PLC 扩展模块……）只提供  
**RS-485 串口 + Modbus-RTU 协议**，通信距离长、抗干扰强，但有个共同的麻烦：

- **必须有人到现场**：接一根 USB-RS485 线、打开调试软件才能看数据，机房在楼上、  
  设备在车间，看一个数就得跑一趟；
- **一台电脑只能接一路**：传统做法是"一台 PC + 一根串口线 + 一个从机地址"，  
  想同时监控分散在几个机房的十几台仪表，就得十几根线、十几套软件；
- **数据留不下来**：串口调试工具看完就关，历史趋势、越限记录全靠人工抄表；
- **固件更新要拆机**：设备装在配电柜里，升级一次得断电、拆壳、接下载器。

本项目做一个**协议转换网关**，把串口设备"翻译"成网络可访问的 Modbus-TCP  
服务端，再配一套上位机把数据收上来、存下来、画出来：

```
   现场层                     网关层                        监控层
 ┌──────────────┐      ┌────────────────────┐      ┌──────────────────────────┐
 │ 温湿度变送器 │      │  STM32F103 网关     │      │  Linux 上位机             │
 │ 电表 / 流量计│ RS485│  Modbus-RTU → TCP   │ 以太网│  · 多网关并发采集         │
 │ PLC 扩展模块 │◄────►│  + Bootloader 升级  │◄────►│  · SQLite 历史存储        │
 │ (Modbus-RTU) │ 9600 │                    │ 502  │  · 越限告警 + 去抖        │
 └──────────────┘      └────────────────────┘      │  · Web 仪表盘 / REST API  │
                                                    │  · OTA 远程下发固件       │
                                                    └──────────────────────────┘
        ↑ 换别的 RS-485 从机只需改寄存器地址，网关固件不用动
```

对上位机和 SCADA 软件而言，网关就是一个**标准 Modbus-TCP 从站**——组态王、  
Modbus Poll、PLC 都能直接连，不需要任何私有协议或驱动。

## 2. 应用场景

### 机房 / 配电室温湿度集中监控

多个机房里各放一台 KTH2-R30 温湿度变送器（RS-485 输出），每台仪表旁装一个  
本项目网关。上位机跑在一台办公 PC 或工控机上，通过 `config.ini` 配置好各网关  
的 IP 和寄存器地址，即可：

- 在浏览器打开 `http://<上位机>:8080/`，**一屏看到所有机房的温湿度卡片**  
  与 24h / 3d / 7d 历史折线图；
- 把 `temp_high = 35.0` 之类的阈值写进配置，连续 3 次越限就产生一条告警记录  
  （去抖，避免空调启停导致的瞬时抖动刷屏），告警面板自动展开；
- 数据落进 SQLite（默认保留 90 天），可按时间段回查、导出做分析；
- 想接进已有的组态软件？直接让 SCADA 连网关的 `502` 端口读寄存器即可，  
  本项目的上位机不是必需的。

### 老旧串口设备上云改造

现场已有一批 Modbus-RTU 仪表，不想动原有接线和轮询逻辑，只想具备"网络访问

- 远程升级"能力：
- 网关对下位仍是标准的 Modbus-RTU 主站角色，**原有仪表一行代码不用改**；
- 对上位暴露 `502~505` 共 4 路 Modbus-TCP，可同时供多个监控客户端接入；
- 后续要加功能、修 bug，不必派人到现场拆机——上位机通过 TCP `506` 把新的  
  `.ota` 固件推给网关，Bootloader 校验 CRC 后写入 App 分区，失败自动回滚上一版；
- 网关侧事件（启动 / TCP 连接 / 485 故障恢复 / 配置变更）落在 W25Q64 的  
  2048 条环形日志里，现场断电也不丢，事后可追溯。

### 教学 / 二次开发底板

网关固件与上位机全部开源、无 GPU 与商业库依赖，适合作为学习素材：

- **STM32 侧**：FreeRTOS 多任务、W5500 硬件协议栈、DMA + IDLE 中断收帧、  
  W25Q64 文件系统式分区、IWDG 双层看门狗、Bootloader 双分区跳转与回滚；
- **Linux 侧**：epoll + timerfd 事件驱动、HTTP 服务器、SQLite 事务与迁移、  
  配置热加载、异步 OTA 状态机；
- **协议侧**：一份 `ota_protocol_def.h` 被三端（Bootloader / App / 上位机）共用，  
  是"跨平台协议契约如何维护"的完整例子。

## 6. 技术要点

**STM32 网关侧**

- **协议转换**：4 个 TCP Socket 监听 502~505，收到 Modbus-TCP 请求后解析 7 字节  
  MBAP 头，剥离后转成 Modbus-RTU 帧发到 RS-485，从机响应再补回 MBAP 转成 TCP 回复。
- **非阻塞状态机**：4 个 Socket 共享一条 RS-485 总线，用  
  `SOCK_PHASE_IDLE / SOCK_PHASE_TX_WAIT` 两阶段状态机代替"一发一收"阻塞写法，  
  避免等响应的 Socket 卡死其余 3 个。
- **三层并发保护**：共享缓冲互斥锁 `g_buf_mutex`（事务期间持有）+ `g_rtu_busy`  
  快速门闩（同一时刻只允许一个 Socket 跑 RTU 事务）+ `g_modbus_mutex` 物理总线锁  
  （防止与 60s 健康巡检任务撞车）。
- **W5500 BSB 区块寻址**：`SOCK_REG(n)=1+4n`、`TX_BLOCK(n)=2+4n`、`RX_BLOCK(n)=3+4n`  
  （网上流传的 `2+n*3` 是 W5100 时代的错误公式，本项目踩过坑并修正）。
- **RS-485 帧捕获**：DMA 循环模式 + USART2 IDLE 中断，靠剩余 DMA 计数反推帧长；  
  发送侧死等 TC 标志（不是 TXE）并关闭回显中断。
- **配置持久化**：网络参数 / 端口 / 报警阈值存 W25Q64，CRC32 校验，失败自动回退默认值。
- **环形日志**：W25Q64 上 2048 条事件日志（启动 / TCP 连接 / 485 故障恢复 / 配置变更），  
  消息队列 + 异步写入任务，队列满则丢弃（日志可丢，业务不可阻塞）。
- **双层看门狗**：软件看门狗任务每 2s 检查 4 个任务心跳（15s 无心跳判死），  
  需**连续两次全员存活**才喂硬件 IWDG（超时 6.4s，超时直接复位）。

**Bootloader（`stm32-gateway/Bootloader/`）**

- 占用 0x08000000 起 16KB，App 从 0x08004000 开始（`APP_ADDR`），上限 48KB  
  （`APP_MAX_SIZE = 0xC000`）。
- 固件暂存于 W25Q64 `0x010000`，**256B 流式 CRC32** 校验通过才写入 App 分区。
- 19 字节控制块（magic `0xA5A5A5A5`）记录升级状态；`fail_flag` 3 字节独立  
  1→0 改写（Flash 只能 1→0，因此无需擦除即可递减），形成"3 次机会"重试机制。
- 升级前把当前 App 备份到 `0x01C000`，新固件 CRC 不一致或启动失败 3 次则自动回滚。
- 跳转前完整复位外设：关中断、清 NVIC、关 SPI/I2C/USART/DMA 时钟、GPIO 复位、  
  切回 HSI、重设 MSP 与 VTOR。

**Linux 上位机（`linux-host/`）**

- **多网关并发**：1 个 epoll + N 个 timerfd + 1 个 eventfd，每个网关按自己的周期  
  采集，互不阻塞（上限 16 个网关）。
- **断线重连 + 故障隔离**：`EINPROGRESS` 配 `poll(POLLOUT)` + `getsockopt(SO_ERROR)`  
  判断延迟连接结果；单网关连续 3 次失败才强制断开重连，其他网关不受影响。
- **存储**：SQLite3（WAL 模式 + 预编译语句绑定 + 事务批量提交），按 `retain_days`  
  自动清理并通过 `wal_checkpoint(TRUNCATE)` 收缩 WAL。
- **HTTP 服务**：手写 HTTP/1.0 服务器（无第三方框架），8 条路由 + Chart.js 仪表盘。
- **报警去抖**：4 通道对称计数（连续 N 次超限才触发，连续 N 次恢复才解除），  
  阈值 ≤ 0 表示该通道不启用。
- **配置热加载**：`kill -HUP <pid>` 运行时重载 `config.ini`，增删改网关即时生效、  
  采集定时器随之启停。
- **OTA 下发**：通过 TCP 506 向网关推送固件，START→DATA×N→FINISH 两阶段 ACK；  
  `RSP_BUSY` 不计入重试次数（总超时 30s），成功后轮询 502 端口确认新固件上线。

## 7. 构建与运行

### 网关固件（Keil MDK）

1. 用 Keil MDK5 打开 `stm32-gateway/MDK-ARM/modbus-gateway.uvprojx`，编译下载。
2. Bootloader 单独打开 `stm32-gateway/Bootloader/Bootloader.uvprojx` 编译，  
   烧写到 `0x08000000`（App 烧写到 `0x08004000`）。

### Linux 上位机

```bash
sudo apt install gcc make libmodbus-dev libsqlite3-dev     # Ubuntu/Debian 依赖
cd linux-host
make            # 产出 bin/modbus-backend
make run        # 编译并启动（自动创建 data/ 目录）
```

详细接线、端口配置与排查表见 [`stm32-gateway/NET/context.md`](stm32-gateway/NET/context.md)；  
网关固件细节见 [`stm32-gateway/README.md`](stm32-gateway/README.md)；  
上位机细节见 [`linux-host/README.md`](linux-host/README.md)。

## 8. 关键协议契约

三端（Bootloader / App / Linux 上位机）共用同一份定义  
（`linux-host/include/ota_protocol_def.h`），保证字节序与常量零漂移。

| 项         | 值                                                                                                | 说明                      |
| --------- | ------------------------------------------------------------------------------------------------ | ----------------------- |
| 命令帧 magic | `0x4F544143`（"OTAC"）                                                                             | 16 字节定长                 |
| 数据帧 magic | `0x4F544150`（"OTAP"）                                                                             | 12 + N 字节（N ≤ 512）      |
| 状态帧 magic | `0x4F544153`（"OTAS"）                                                                             | 12 字节                   |
| 控制块 magic | `0xA5A5A5A5`                                                                                     | 19 字节，含 3 字节 fail_flag  |
| 固件头 magic | `0x504A3142`（"PJ1B"）                                                                             | `.ota` 文件头 16 字节        |
| 命令码       | `START=0x00 / FINISH=0x01 / CANCEL=0x02 / STATUS=0x03`                                           |                         |
| 响应码       | `ACK=0x06 / NACK=0x15 / ABORT=0x18 / BUSY=0x19 / ERR_ERASE=0x1A / ERR_WRITE=0x1B / ERR_OOB=0x1C` |                         |
| 单包大小      | 512 B                                                                                            | `OTA_PACKET_SIZE`       |
| 升级端口      | 506                                                                                              | `OTA_PORT`              |
| 响应超时      | 5 s（START 放宽到 10 s）                                                                              | 设备端 START 同步擦除最坏 ~4.4 s |

Modbus 应用层约定：温度 `0x0300`、湿度 `0x0301`（保持寄存器，从机地址 1），  
原始值放大 10 倍存为 int16（`0xFFCB` → `-53` → `-5.3℃`），因此能表达零下温度。

## 9. 实测数据

下表数值均在**真实硬件平台**上测得：STM32F103C8T6 网关板（W5500 + W25Q64 + DS3231 +  
MAX485）接 KTH2-R30 温湿度变送器，Linux 上位机跑在 x86 PC 上，网关与上位机经交换机直连。

| 指标                  | 数值        | 条件                                |
| ------------------- | --------- | --------------------------------- |
| RS-485 ↔ TCP 单次转换延迟 | < 20 ms   | 9600 8N1，读 2 个寄存器                 |
| 4 路 Socket 并发       | 无相互阻塞     | 共享单条 RS-485 总线                    |
| RS-485 健康巡检周期       | 60 s      | 连续 3 次失败判故障                       |
| 硬件看门狗超时             | 6.4 s     | IWDG 预分频 64 / RLR 4000（LSI 40kHz） |
| 软件看门狗判死门限           | 15 s      | 某任务无心跳                            |
| 网关日志容量              | 2048 条    | W25Q64 环形缓冲，队列深度 64               |
| OTA 单包大小            | 512 B     | 总超时 30 s（BUSY 不计数）                |
| OTA 固件上限            | 48 KB     | App 分区 `0xC000`                   |
| OTA 全流程耗时           | 约 10~20 s | 48KB 固件 + 擦除 + 校验 + 重启确认          |

固件侧验证：`.ota` 打包脚本内置回读自检（`struct.unpack` 逐字段 assert），  
Bootloader 每次烧写后回读 CRC32 比对，任何一步不一致都不跳转、直接回滚。

## 10. 说明

- RS-485 是半双工单总线，任一时刻只能有一个 Modbus 事务在途（靠门闩串行化），  
  高并发场景下吞吐受限于总线速率而非网络。
- 4 个 TCP Socket 共用收发缓冲以省 RAM，事务期间串行使用。
- App 分区上限 48KB，应用规模增大需重新划分 Flash 布局。
- 配置以明文存于 W25Q64，未做加密。
- 上位机的 HTTP 服务为自用级实现：HTTP/1.0 + `Connection: close`，未处理  
  HTTPS、鉴权、目录穿越校验与高并发。
- 上位机 OTA 的目标 IP / 端口目前硬编码（`ota.c` 中标注 TODO），未从 `config.ini`  
  的 `[ota]` 段读取。
